# 实施与验收

## 概览

首个验证项目建议采用 30–60 秒、2 个主要角色、1–2 个场景、8–12 个镜头。目标是完成一条可审查、可恢复、可核算成本的制作链，再扩展整季制作和更多供应商。

具体阶段排期、开发 Token 预算和持续交付节奏见[开发计划与资源预估](development-plan.md)。本页维护功能验收标准。

## 开发里程碑

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| 项目与创作 | 项目首页、创建、规划、剧本、版本和审查 | 每份内容可编辑、提交、退回、批准和恢复 |
| 专业助手基础 | 页面角色映射、Agent 配置、独立工作记录和修改提案 | 切页不自动执行；只在确认后应用草稿，角色实际能力可核对 |
| 共享资产与分镜 | 角色、场景、道具、镜头依赖和粗预演 | 修改设定能定位受影响对象，旧版本仍可访问 |
| 可控图像制作 | 一个生图后端、局部修改、授权和原图入库 | 无授权不提交；候选采用与付费授权分开 |
| 视频与成片 | 一个视频后端、声音、基础时间线和导出 | 长任务恢复、版本绑定和最终导出可验证 |
| 制作优化 | 返工原因、素材复用、更多可控输入 | 用真实试片数据验证成本和时间改善 |

## 关键验收

每条拒绝规则同时验证允许路径和拒绝路径。图像效果图不作为自动化行为测试。

- 未批准的分镜不能提交正式生成；批准后仍需要本次制作授权。
- 输入、模型、数量或有效参数变化后，旧授权不能提交。
- 并发任务先预占额度，合计不能突破授权范围；待核实费用不能提前释放。
- 角色改版只标记依赖该角色的镜头；无关道具镜头不受影响。
- 批准版本不能原地覆盖；采用新版输入形成新草稿，历史可查询。
- 任务恢复优先查询既有远端任务，不盲目重复提交。
- 原始文件与预览分别保存；重新打开项目后素材和审查信息仍可访问。
- 连续性检查报告定位到对象、镜头、时间点或图像区域；最终采用需要人工决定。
- 项目隔离在服务端校验；受限子 agent 无法跨项目读写或通过其他工具绕过授权。
- 剪辑导出绑定已批准时间线和素材版本；修改时间线形成新的待审版本。
- 页面分别加载正确的专业角色、skills、MCP 工具和配置版本，不能仅替换名称。
- 切页、换集和换镜头不启动模型；在途结果仍归入原对象。
- 重新进入工作区恢复对应角色记录，不将其他角色闲聊自动注入当前任务。
- 用户先手工修改后，旧提案不能覆盖新值；锁定字段不能通过批量应用绕过。
- 应用建议只修改草稿；新建项目、正式批准、付费生成和导出保持独立操作。
- MCP 写入及收费工具与原生工具接受同样的权限和额度检查；检查角色无法批准内容。
- 角色配置发布只影响规定范围的新任务，agent 不能自行修改角色、工具或额度。

开发需安排领域服务测试、供应商真实 API 测试、无 key 的会话回放、客户端交互测试及真实工作流演示。新增模型可见事件和 SDK 投影时，同步覆盖 TypeScript 与 Python 消费者。

## 效果指标

记录每张被采用关键帧成本、每秒被采用视频成本、每镜头返工次数及原因、人工审查时间、资产复用情况和总交付时间。样本同时记录供应商、模型、有效参数和输入资产版本，避免把不同条件下的结果直接比较。

这些指标用于试片后的实测决策，不预先承诺减少抽卡的比例。自动检测结果只能作为候选筛选和定位依据。

## 待决定事项

| 事项 | 初始建议 |
| --- | --- |
| 品牌 | 目录名称使用 Multica；页面 DSH 标识在正式视觉设计时统一 |
| 第一版部署 | 本地单人工作台，架构保留身份和项目权限字段 |
| 图像供应商 | 先选一个实际支持参考图和编辑能力的后端，进行小样本验证 |
| 视频供应商 | 先选一个可查询任务和费用信息的后端 |
| 画幅与风格 | 由首个试片项目确定，不把样例画风写成全局限制 |
| 预算 | 用户配置额度，供应商报价与示例预算分开 |
| 高级功能 | 复杂口型、角色训练、多用户实时协同和专业剪辑交换格式后续评估 |

参考图与分步编辑的能力示例见 [Runway 官方指南](https://help.runwayml.com/hc/en-us/articles/40042718905875-Creating-with-Gen-4-Image-References)，条件控制示例见 [ComfyUI ControlNet 文档](https://docs.comfy.org/tutorials/controlnet/controlnet)。这些资料说明可选机制，不构成当前项目已接入的声明或对特定供应商效果的保证。
