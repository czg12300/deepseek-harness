# 开发计划与资源预估

## 概览

本计划以现有功能方案和 17 个主要页面为范围，目标是交付可完成一段漫剧试片的本地单人版本。采用“1 名全职开发者配合 AI 辅助开发、每周 5 个工作日”的估算基准。

预计基础工作量为 50–70 个开发人日；加入 20% 排期缓冲后，完整试制版本约需 12–17 周。预计开发模型消耗为 710–1,200 万 Token；加入 35% Token 风险预留后，建议准备约 960–1,620 万 Token，以约 1,300 万 Token 作为初始规划中值。

这些数字是基于工作拆解的规划估算，尚未用 Multica 的真实开发吞吐量校准，不是报价、性能测量或完成期限承诺。阶段 S0 和 S2 完成后需要用实际消耗重估剩余工作。

本文件只安排未来开发，不启动实现、生成任务、自动化、发布或持续运行的 agent。

## 估算假设与范围

### 人员与工作方式

- 1 名能同时处理 TypeScript、React、插件集成和基础数据库开发的全职开发者负责实现与集成；每天按约 6 小时有效工程工作估算。
- AI 用于代码阅读、实现、测试修复、文档和审查；所有开发模型和开发子 agent 的用量合并统计，不把“多 agent”当作免费并行资源。
- 创作者每周参加两次 30–45 分钟的产品审查，并在阶段交付时安排约 45 分钟验收；通常在 1 个工作日内反馈。长期等待反馈会增加实际日历时间。
- 复用当前 Harness 的 agent、工具、Session、附件、Web 和子 agent 能力。先固定基座版本，避免开发过程中持续追随其全部 API 变化。
- 估算包含阶段内测试、普通修复、代码审查和随功能更新的文档；额外缓冲处理接口变化、较大返工及不可预期等待。

### 本轮交付范围

覆盖项目管理、创作规划、剧本、共享设定、分镜、关键帧、视频、基础剪辑、审查、任务、服务和 Agent 配置等 17 个主要页面的一版可用功能。每个页面以完成主要任务为准，不按效果图中所有装饰和示例控件机械扩展范围。

专业角色使用[专业 Agent 工作区](agent-workspaces.md)定义的 9 个角色配置。按制作阶段逐步启用真实能力，复用统一对话、提案、权限和会话组件，不分别开发 9 套聊天系统。

媒体集成限定为一个图像后端、一个视频后端，以及基础声音导入和一个声音生成入口。后端需具备实际所需能力；未验证的高级输入不承诺交付。剪辑包含镜头编排、裁切、基础静帧运动、配音、字幕、环境音和单集导出。

首个验收样本为 30–60 秒、2 个主要角色、1–2 个场景、8–12 个镜头。允许混合使用静帧、有限动画和生成视频；不要求每个镜头都调用视频模型。

### 不计入本轮

不包含多人实时协同、云端 SaaS 账户与计费、移动端独立应用、模型训练或角色 LoRA 训练、完整专业剪辑软件能力、复杂口型系统、多供应商智能竞价、海量素材检索及整季无人值守生产。这些需求需要另行估算。

现有设计图和此前讨论的消耗不计入未来开发 Token。产品运行时的用户创作 Token、图像和视频生成、语音服务、存储、网络及 CI 资源费用另行预算。

## 阶段工作量与 Token

Token 列为输入与输出合计，单位为百万 Token；1M 等于 100 万。阶段数字不含末尾额外预留。人日表示开发者投入，不是 AI 连续运行的小时数。

| 阶段 | 主要范围 | 基础人日 | 开发 Token（M） | 对应交付 |
| --- | --- | --- | --- | --- |
| S0 可行性与交付基础 | 固定基座、验证插件和关键后端、确定数据与发布方式 | 3–4 | 0.3–0.5 | 可启动的集成骨架和已验证风险清单 |
| S1 项目与版本基础 | 项目首页、创建、持久化、导航、项目设置基础 | 5–7 | 0.6–1.0 | 可建立、保存并重新打开的真实项目 |
| S2 专业助手与文本闭环 | 角色配置、独立工作区、提案应用、大纲、分集和剧本 | 8–10 | 1.1–1.8 | 可对话修改并人工定稿的文本工作台 |
| S3 资产与分镜 | 角色、造型、场景、道具、镜头与依赖、连续性报告 | 7–9 | 0.9–1.4 | 可维护一致设定并审查镜头的工作台 |
| S4 可控生图 | 一个后端、关键帧、局部修改、制作授权、预算与任务记录 | 7–10 | 1.2–2.0 | 首条真实、可核算的关键帧制作链 |
| S5 视频与任务恢复 | 一个视频后端、首帧与动作方案、查询、取消和恢复 | 7–10 | 1.2–2.0 | 可审查、可恢复的视频候选制作链 |
| S6 声音与剪辑成片 | 声音导入与生成、字幕、基础时间线、预演和导出 | 7–10 | 1.0–1.8 | 第一段可播放、可重建的粗剪和成片 |
| S7 试片与交付加固 | 完整试片、回归、恢复、使用文档、缺陷和交付打包 | 6–10 | 0.8–1.5 | 可反复使用的本地试制版本 |
| 合计 | 本轮功能范围 | 50–70 | 7.1–12.0 | 端到端试片闭环 |

排期按基础 10–14 个工作周乘以 1.2 计算，得到约 12–17 周。Token 按基础 7.1–12.0M 乘以 1.35 计算，得到约 9.6–16.2M。两种缓冲分别针对时间和模型用量，不再额外叠加一次相同风险预留。

### 预计可体验节点

以正式启动后的相对周数表示，不指定未经确认的开工日期。时间区间包含排期缓冲，阶段依赖保持顺序。

| 节点 | 预计时间 | 创作者能够实际做什么 |
| --- | --- | --- |
| 项目基础版 | 第 2–3 周 | 建项目、保存资料、切换和重新打开项目 |
| 文本创作版 | 第 4–5 周 | 使用策划与编剧助手、查看差异、应用草稿、提交审查 |
| 资产分镜版 | 第 6–8 周 | 管理共享设定、拆镜头、检查引用与变更影响 |
| 关键帧版 | 第 8–10 周 | 审查生成单、制作图片、局部返工、采用候选 |
| 视频制作版 | 第 9–12 周 | 从批准画面制作片段，检查失败、取消和恢复 |
| 首段粗剪 | 第 11–15 周 | 加入声音字幕、调整节奏、预览并导出试片 |
| 稳定试制版 | 第 12–17 周 | 完成整条工作流并重复开展第二次制作 |

若每周只有约一半开发投入，开发相关日历时间应近似按两倍规划；增加开发者不会使周期线性减半，数据模型、授权和供应商接入仍有顺序依赖。本计划不把额外人员或全天候多 agent 执行作为隐含前提。

## 阶段交付和验收

每阶段交付能操作的纵向功能链，包含数据、服务、界面、验证和文档。没有真实接入的能力明确显示未配置或不可用，不把静态页面、演示数据或 mock 返回视为正式完成。

### S0：先验证会决定返工规模的部分

交付统一启动的插件骨架、基座依赖记录、最小数据库迁移与恢复样本，以及角色 Session、图像后端、视频任务查询和媒体导出的窄范围技术验证。图像、视频和声音调用使用用户单独授权的小额度测试预算。

验收重点是验证必要能力确实可接入、取消与查询语义可说明、原件可保存，以及发布和回退方式可执行。无法验证的供应商条件写入阻塞项，不以 mock 宣称通过；不依赖该后端的阶段仍可继续。

### S1：先让项目数据真实存在

交付项目首页和创建流程、项目与单集导航、草稿保存、不可变版本基础、归档与恢复，以及真实项目读取接口。新项目不自动启动 agent 或媒体生成。

验收包括重启后恢复项目、两项目之间的数据隔离、保存冲突提示和历史版本不被覆盖。该阶段建立后续对象通用机制，不一次性完成所有高级资产字段。

### S2：建立专业 agent 的完整文本链

交付统一右侧对话面板、角色配置版本、Skills 与具体 MCP 工具选择、工作区会话绑定、提案差异、字段锁定与部分应用，以及大纲、分集和剧本编辑。

先激活策划和编剧能力，登记其余角色并准确显示可用状态。验收“发送需求 → 提案 → 查看差异 → 应用草稿 → 人工批准”的真实闭环；同时验证切页不执行、在途任务不换目标、旧提案不覆盖手工修改和角色不能自审批。

### S3：把资产与镜头关联起来

交付共享资产、参考图导入、角色与造型分版、场景布局、道具状态、剧本到镜头的引用和分镜导演对话。角色设计、美术和连续性检查角色按已具备工具启用，尚未开放生图时只提交可编辑方案。

验收一项上游变更能够定位受影响镜头，用户可选择是否迁移；迁移建立新草稿，不覆盖旧产物，不触发新生成。连续性报告给出具体对照对象，不仅输出泛化评价。

### S4：把费用控制放在首次真实生图之前

交付服务连接、有效参数解析、生成请求冻结、人工授权、额度预占、持久化任务与尝试记录，再接入关键帧生成、局部修改、候选对比和原图入库。

验收无授权不提交、请求变更后授权失效、并发不能超出额度、未知提交状态不盲目重试，以及成功结果只作为候选。生图助手只通过这些服务执行，MCP 不能绕过。

### S5：复用任务机制接入视频

交付视频助手、批准输入画面引用、动作与运镜方案、实际视频后端、状态查询、取消反馈、重启恢复、片段审查及采用。

验收本地停止等待与远端取消的区分、任务恢复不重复计费提交、待核实费用不提前释放，以及片段质量采用必须由用户决定。后端缺少某项控制时明确限制界面，不静默丢弃参数。

### S6：用基础剪辑交付可播放作品

交付剪辑助手、声音导入和一个受控声音生成入口、字幕、视频与音频轨、裁切、简单转场或静帧运动、时间线版本、粗预演和单集导出。

验收修改提案可预览后应用、声音与镜头引用明确、正式导出使用批准版本，且能根据保存的时间线和原件重新合成。先满足试片，不同时开发完整专业剪辑器。

### S7：用一次完整制作校准产品

完成约定试片，处理主流程缺陷、恢复与回退问题，补充使用说明、故障诊断和数据备份说明。对模型能力不足的镜头记录人工处理或替代制作方案，不无限抽卡。

验收依据[实施与验收](delivery-plan.md)，并记录每张采用关键帧成本、每秒采用视频成本、返工原因、人工审查时间和总交付时间。产品完成条件是主流程可靠可重复，不是生成模型在所有场景中都能达到同等质量。

## 持续交付安排

### 节奏

| 频率 | 活动 | 产物 |
| --- | --- | --- |
| 每个工作日 | 更新任务状态、阻塞、实际 Token 和剩余估算 | 简短开发记录，不要求每天发版 |
| 每 2–3 个工作日 | 完成一个可验证的小功能，持续集成到候选分支 | 小范围变更、验证结果、功能说明 |
| 每周两次 | 与创作者确认交互与业务行为 | 明确的通过或修改意见 |
| 每周一次 | 提供可启动的预览候选 | 可操作入口、演示、已知限制和数据注意事项 |
| 每两周或阶段完成 | 汇总已经验收的功能发布试用版本 | 版本说明、回退方式、累计用量和下一阶段范围 |

预览交付可以增量发布，内容以已完成的小功能为准。上表是人工开发流程安排，不创建定时任务或自动部署；实际开始开发和启用发布流程需要后续明确启动。

### 每次交付应包含什么

- 一个明确的用户操作路径及可观察结果，说明真实接入与暂不可用功能。
- 与本次改动相称的行为验证；权限、版本、费用和恢复路径同时验证允许与拒绝情况。
- 用户可见 GUI 改动提供按仓库要求录制的真实运行演示；模型输出改动补齐相应会话回放，不能用设计图代替。
- 更新功能文档及必要的决定记录；注明配置、数据迁移、备份和回退条件。
- 报告实际开发 Token、阶段累计值、媒体测试费用及下一批任务，三者分开统计。

本地检查按改动范围选择，CI 承担完整覆盖与平台矩阵。不为每次提交无条件重复全仓库测试；发布候选需满足约定主流程的验收证据。

### 版本与回退

每个预览候选固定代码、基座和配置版本。未完成能力通过显式配置关闭，已可用路径不能依赖未合入功能。合入前进行代码审查，单个变更保持足够小以便定位失败。

数据库迁移前备份并验证恢复；有数据格式变化时，不能把切回旧代码等同于安全回退。回退需同时匹配数据库和素材清单，不能覆盖既有 Session 记录或批准产物。

当关键主流程失败时暂停推广该候选，保留用户可用的上一版本。修复后只重复被改动影响的检查及必要回归，不继续在失效版本上叠加大批功能。

## Token 统计与预算管理

### 统计口径

开发 Token 按所有开发模型请求的输入与输出累计，包含代码阅读、编码、测试诊断、审查、文档和开发子 agent。重复发送的上下文按每次请求计入；工具产生的文字在进入模型请求时计入输入，纯工具执行或编译等待本身不产生语言模型 Token。

缓存输入通常属于输入 Token 的子集，不能在输入总量之外再次相加。模型若单列推理 Token，按供应商的用量字段定义处理，避免与输出总量重复计算。不同模型分别记录原始用量，合计仅用于工作量预算。

Token 数量不等于统一货币费用，也不直接换算为 ChatGPT 或 Codex 订阅额度百分比。价格依赖实际模型、缓存、输入输出费率和服务方案；本计划不假设具体价格。

### 估算依据

阶段预算采用工作拆解估算。一个中值量级校验示例为：约 180 个工程小任务，每个平均 5 次模型请求，每次约 9,000 输入 Token 加 1,600 输出 Token，合计约 9.54M。加入 35% 预留约为 12.88M，与约 13M 的规划中值相符。

示例参数不是实测请求日志。大型类型问题、重复全库阅读、跨插件调试、长上下文审查或低缓存命中会增加消耗；更小任务、精确检索、结构化交接和复用组件可能降低消耗。

预算若需要拆分输入输出，可暂按约 85% 输入、15% 输出规划；实际以用量记录为准。以 13M 为例，约为 11.05M 输入和 1.95M 输出，其中缓存比例尚未知。

### 预留如何分配

35% 预留按基础 Token 预算的比例规划：约 15 个百分点用于跨插件调试和集成返工，10 个百分点用于产品审查调整，10 个百分点用于基座与供应商差异。阶段内普通修复已包含在基础值中，这部分只覆盖超出原工作拆解的风险。

### 用量控制与重估

- S0 完成后统计每类工程任务的请求数、平均上下文和输出，替换示例参数，发布第一次剩余估算。
- S2 完成后用专业助手和数据主线的实际集成成本重估 S3–S7；固定后续范围和供应商条件。
- 每阶段实际累计超过阶段 Token 上限的 80%，但验收项尚未完成一半时，先定位原因并调整任务拆分。
- 预计将突破某阶段上限或动用额外预留时，报告剩余范围、原因和可选缩减项；阶段预算只是预估，真实付费额度由用户另行设定。
- 预计突破整体 16.2M 或 17 周上界时，重新确认范围和资源，不静默扩大投入，也不把未完成项标记为交付。
- 每阶段剩余估算按“已完成实际值 + 剩余任务的更新估算”计算，不机械延续最初总数；实际用户等待和服务停机另行记录。

每周至少记录：阶段、完成的可验收项、模型、请求数、输入 Token、其中缓存输入、输出 Token、实际费用（若可取得）、测试媒体费用、耗时和阻塞。缺少平台用量数据时标记为估算，不能声称是精确消耗。

## 依赖与风险

关键顺序为“项目与版本 → 角色与提案 → 资产与镜头依赖 → 生成授权与任务 → 图像 → 视频 → 剪辑与试片”。不能先开放真实付费工具，再补授权与额度检查。

| 风险 | 对进度或用量的影响 | 处理方式 |
| --- | --- | --- |
| 基座 API 变化 | 消费者、构建和会话投影返工 | 固定版本，集中升级，先评估影响 |
| 供应商能力或凭据不满足 | 图像或视频阶段无法真实验收 | S0 提前验证；未满足条件时不承诺该阶段完成 |
| Agent 越权或会话串用 | 需要重做关键执行路径 | S2 优先验证身份、对象范围、配置和提案机制 |
| 视频长任务结果不确定 | 重复提交风险、费用难结算 | 持久化请求和查询，未知状态暂停重试 |
| 生成效果不稳定 | 试片返工消耗增加 | 单独设置测试额度，采用局部修正与混合制作 |
| 时间线功能持续膨胀 | 超过基础剪辑工作量 | 限定首版编辑动作，高级能力另列计划 |
| 用户反馈或外部服务长期等待 | 日历周期增加 | 记录等待天数，推进无依赖工作并重排里程碑 |

若必须更换主要媒体后端、支持多租户部署或实现完整专业剪辑能力，需要重新估算，不能假定均可由当前缓冲吸收。

## 启动条件与调整规则

正式开发前确认开发者投入、目标运行环境、首个试片规格，以及可用于验证的供应商账户和测试额度。凭据通过安全配置提供，不写入本文档。

在开始 S4 前必须确定图像后端、费用口径和审批规则；在 S5 前确定视频后端的任务查询及取消语义；在 S6 前固定导出规格和声音来源。未满足条件时标记依赖阻塞，不用演示接口代替验收。

功能新增进入待办列表，先说明影响哪个里程碑、增加多少工作及 Token，再决定替换现有范围或延长周期。设计图调整不会自动成为额外功能承诺。

本计划与[功能设计](feature-design.md)、[专业 Agent 工作区](agent-workspaces.md)、[工程方案](architecture-design.md)和[实施与验收](delivery-plan.md)共同构成开发输入；本文件是排期与 Token 估算的唯一维护位置。
