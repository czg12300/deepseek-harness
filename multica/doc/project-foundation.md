# 项目基础版

## 概览

项目基础版对应[开发计划](development-plan.md)的 S1。它提供真实项目、手工文本草稿和版本管理；完整专业助手及制作流程仍按后续阶段交付。界面依据[页面规格](page-specifications.md)和项目首页、新建项目、项目设置的[设计图](design-catalog.md)实现。

## 入口与使用流程

在现有 Web 应用最左侧工具栏选择“漫剧”，打开“全部项目”。基础版不需要模型 API Key；出现模型配置提示时可选择“稍后配置”。新建项目时填写名称、构想和画幅；目标集数及每集时长可以留空。已有剧本可从 UTF-8 编码的 `.txt` 或 `.md` 文件导入，保存来源正文，不自动拆集或调用模型。

创建后进入故事大纲。项目内侧栏提供大纲、分集规划、具体分集、项目设置和版本历史。手工添加分集后可编辑标题与剧本；目标集数本身不会自动生成分集。选择“保存草稿”将当前项目内容写入数据库。

从“返回全部项目”或项目选择器切换作品。首页支持名称搜索、排序，以及进行中和已归档筛选。项目设置可以修改基本信息与制作规格，也可以归档或恢复项目。归档保留数据及历史，并由服务端阻止内容修改。

## 保存与历史

每次内容保存产生一个不可变项目版本，包含当时的规格、大纲、来源正文及全部分集草稿。历史内容可查看；恢复为新版本会追加记录，不改写旧版本。

保存使用打开草稿时的预期版本。如果另一窗口已保存更新，当前保存会提示冲突并保留本地草稿。先比较当前项目与本地内容，再选择导出草稿、加载已保存版本，或明确以本地内容建立新版。最后一种操作会替换整份项目内容，不能当作自动合并。

文件夹项目的编辑缓冲自动保存为恢复草稿，不改变正式内容版本；重新打开时保留它原先依据的版本，以便处理冲突。保存失败时保留页面中的内容并提示错误。关闭前使用“保存草稿并关闭”；归档及历史恢复前应先处理未发布修改。尚未提交的聊天输入和未发布的角色配置仍需在当前设备处理。

## 本地数据

新建作品先选择一个新的或空的项目文件夹。该目录保存 `multica.project.json`、`project.sqlite`、`sessions/` 中的专业对话，以及 `assets/`、`artifacts/` 和 `exports/`。在另一台设备选择“打开项目文件夹”即可恢复内容；模型账号与插件仍在各设备配置。默认 `$DSH_HOME/multica/studio.sqlite` 保存本机最近位置、角色模板和旧项目；旧项目可从界面迁出为独立目录，源数据保留。配置与持久化规则见[项目服务](../../packages/multica/studio-core/README.zh.md)。

复制项目或弹出硬盘前，使用“保存草稿并关闭”，等待文件释放成功。项目设置也提供“保存、复制并关闭项目”，目标必须是空目录。同一项目的两个副本不能同时打开，副本之间不自动合并。移除最近位置只清理本机入口，不删除文件。目录缺失、项目占用和不支持的格式均明确报错；实物移动硬盘与跨操作系统运行尚需单独验证。

## 当前范围

专业对话与人工文本审查见后续的[文本创作工作台](text-authoring.md)。共享角色与场景、生图、视频、预算执行、剪辑和导出尚未接入，不以示例数量展示制作进度。项目创建、保存、切页和切集均不调用模型或付费服务。

S0 中媒体供应商、远端任务恢复和成片导出的技术验证不属于此次项目数据闭环的完成声明。它们仍需实际后端及单独授权的测试额度，详见[实施与验收](delivery-plan.md)。
