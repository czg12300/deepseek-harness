# 演员库

## 入口与界面

“全部项目”和“演员库”在同一漫剧工作台的页头组成两个 Tab；点击直接切换下方内容，不改变浏览器地址。演员库 Tab 沿用项目列表的黑白色板、边框、间距和按钮。顶部显示已选演员库、创建、导入、导出入口；下方提供姓名搜索、时代及地区筛选，网格卡片显示头像和姓名。点开卡片编辑演员名称、介绍、时代、地区和两张参考图。演员资料由用户填写，不触发模型或媒体生成。

## 数据位置与身份

默认根目录是 `$DSH_HOME/multica/actor/`，与系统数据库 `$DSH_HOME/multica/studio.sqlite` 同级。每个演员库占一个按稳定 UUID 命名的子目录，包含 `actor-library.json`、`library.sqlite` 和 `assets/<actor-id>/`。演员库、演员分别使用独立 UUID；移动或复制完整子目录不会改变身份。`library.sqlite` 保存演员资料和相对素材路径；图片文件保存在库目录内，不依赖原设备的绝对路径。项目数据库与演员库数据库互不引用，项目删除、归档和迁移不影响演员库。

```text
$DSH_HOME/multica/
  studio.sqlite
  actor/
    <演员库 UUID>/
      actor-library.json
      library.sqlite
      assets/
        <演员 UUID>/
          <图片 SHA-256>.png | .jpg | .webp
```

库列表由 `actor/` 的有效清单与数据库共同生成；`studio.sqlite` 不保存演员，也不作为携带演员库的必需文件。演员库数据库包含 `library`（库身份、名称）、`actors`（资料与相对图片路径）和 `imported_actors`（来源演员与目标演员映射）三张表。演员包括姓名、介绍、时代、地区、头像参考图和全身参考图。页面按最近编辑时间分页展示，每页最多 48 位演员；筛选在 SQLite 中完成，避免只搜索当前已加载卡片。

## 导出与合并

导出生成一个 ZIP，包含清单、SQLite 快照及库内引用的图片。导入时先限制总大小、文件数量和解压大小，再校验清单、SQLite 身份、相对路径和每个图片的内容；校验不通过不修改现有库。未选目标库时，导入为独立演员库；选择目标库时，导入到该库并合并。

合并使用演员 ID 判定同一演员。资料和图片相同则跳过；同 ID 但资料不同，保留目标版本，并以新 ID 添加来源版本。来源库 ID 与演员 ID 的映射保存在目标库内，重复导入不会再次增加副本。姓名相同但 ID 不同的演员都保留，避免误合并。合并只有全部校验和素材准备成功后才提交数据库；失败时目标库保持原状。用户可在页面查看新增、跳过和冲突副本数量。

页面提供“导入为新库”和“导入并合并”两个明确入口。后一入口要求先选定目标库。创建库后可在下拉框中切换库；演员卡片打开完整资料进行编辑。保存失败时保留当前表单及错误信息，用户可修正后重试。导出使用浏览器下载，不修改库内容。

## 限制

浏览器导入、导出目前使用有明确上限的 ZIP 数据传输；超限时直接提示，不会产生不完整归档。演员库暂不自动同步到项目角色与造型，后续引用需要显式的项目侧绑定和版本规则。

内置验证覆盖：两个库之间的数据隔离、SQLite 与图片文件落盘、ZIP 完整导出、在新设备安装、重复导入去重、同 ID 冲突保留双版本、恶意路径及缺失图片拒绝，以及真实浏览器中的创建、上传、下载和合并。浏览器传输上限为 ZIP 32 MiB、解压后 64 MiB、500 个文件及每图 2 MiB；更大的媒体库需要后续的流式导入导出通道。
