# 三方授权插件开发计划

[English](2026-09-09-third-party-auth-plan.md) | 中文

## Summary

本计划以已确认的“设置 → 三方授权”原型为输入，交付 ChatGPT 与 Claude 的账号连接、状态展示和模型选择。API Key 沿用现有模型设置。ChatGPT 使用现有 pi-ai Codex 路由；Claude 通过官方 Claude Code 执行，并由官方流程管理登录。本文是待实施计划，不表示登录或连续会话已经通过验证。

Owner: 三方授权功能实施者。Created: 2026-09-09。Expires: 2026-10-09。Promotion target: 实施时形成对应包的 README、子系统文档和 Agent Note；完成后删除本临时计划。

## 开发进度

代码集中在 `packages/third-party-auth/` 的三个包：`third-party-auth`（Host 及 Provider）、`client-ui-third-party-auth`（设置页和独立 Claude 窗口）、`third-party-auth-bundle`（组合层）。原有业务模块未改动；共享变更限于编译/依赖清单、文档索引及生成产物。

构建、Profile 加载、真实 Web 设置页和针对性测试已验证。Claude 连续会话的模拟 SDK 用例覆盖续聊、模型选择、拒绝权限和断开；最新两个真实原生运行时探测已通过，早期 Node 子进程 SIGKILL 的原因尚未定位。真实账号 OAuth 与模型推理尚未验收，整项工作不能标记为验收完成。

## 范围与交互

新增独立设置子项“三方授权”，排序在“模型”之后、“插件”之前。设置壳通过已有 `settings.section` 注册入口，登录页拥有自己的文案和状态；不把入口塞回模型卡片。首版每个 Provider 连接一个账号，支持重新连接和断开连接，不做账号池、共享额度或自动轮换。

| 页面元素 | 目标行为 |
|---|---|
| ChatGPT 卡片 | 展示连接状态；通过授权链接完成登录；登录后展示可取得的账号信息和模型选择 |
| Claude 卡片 | 展示 Claude Code 运行条件及连接状态；调用官方登录流程；完成后展示模型选择 |
| 默认模型 | 持久化该 Provider 的新会话默认值；不覆盖其他 Provider 的默认值或进行中的请求 |
| 会话模型选择 | GPT 走现有请求路由；Claude 走对应会话执行器；同一执行器内的切换在下一轮生效 |
| 断开连接 | 取消该页面拥有的授权尝试，禁止新的使用；保留历史记录；准确区分解除 Harness 连接与官方全局退出 |
| 异常状态 | 显示取消、超时、授权过期、运行环境缺失、模型不可用及重试入口 |

跨 GPT 与 Claude 切换涉及执行器和会话上下文。首版在已创建的会话中引导新建另一执行器的会话，不静默转换已有上下文。首次打开页面不发起模型推理，不要求输入 API Key，不假设账号邮箱、套餐和额度一定可查询。

<a id="modules"></a>
## 插件分工

用户功能名为“三方授权”，代码使用 `auth` / `authorization`，不使用表示作者的 `author`。新增源码、测试、资源及包文档集中在 `packages/third-party-auth/`；遵守现有 `packages/<group>/<package>/` 两层工作区布局。下面是拟定包位置，不表示这些包已经存在；T1 收敛最终拆包，避免只含转发逻辑的空包。

| 拟定位置 | 职责 |
|---|---|
| `packages/third-party-auth/auth/` | Service Definition 与业务编排：Provider 注册、脱敏连接视图、连接启用状态、模型目录及默认选择；凭证仍属于已有存储或原生客户端 |
| `packages/third-party-auth/chatgpt/` | Provider：调用既有 pi-ai 授权、管理本插件拥有的 Codex 路由、读取支持的模型目录 |
| `packages/third-party-auth/claude-code/` | Provider 与原生运行时适配：官方登录、状态和模型发现、连续会话、取消、审批及事件投影；不读取或保存 Claude Token |
| `packages/third-party-auth/controller/` | Consumer：插件自己的 Typert Remote 命名空间、授权尝试事件、交互回复、调用者归属及错误投影 |
| `packages/third-party-auth/ui/` | Consumer：设置子页、卡片、授权弹窗、模型选择、状态存储及中英文词典；按现有规范分离 Host / Client 编译入口 |
| `packages/third-party-auth/bundle/` | 独立安装层：组合 Host、Client、Provider 和运行时依赖；卸载时释放注册及活跃任务 |

Claude 登录与连续会话共用本组 `claude-code` 包内的原生运行时模块，直接依赖官方 SDK 和已有 subprocess 服务的公开接口。现有一次性 Claude 子任务插件只作为行为和测试参考，不迁移其文件、不抽取其内部代码、不增加它对本组的反向依赖；也不复制已有公共进程管理实现。

<a id="isolation"></a>
## 代码隔离与上游同步

减少 rebase master 冲突是实施硬约束。功能逻辑留在新增目录，原模块原则上只被依赖；注册、配置和状态由插件拥有，不能通过 monkey patch、内部路径导入或复制一整套旧模块换取表面上的零修改。

| 接入点 | 默认策略 |
|---|---|
| 设置导航 | 新 UI 插件注册 `settings.section`，不修改设置壳或既有模型页 |
| 认证与凭证 | 调用现有服务；本插件独立编排，不改写 authorization、credentials 或 pi-ai 内部流程 |
| API 与状态 | 使用独立 Remote 命名空间、设置命名空间和客户端 store，不往现有 settings/session 控制器堆业务 |
| Claude 执行 | 独立运行时和生命周期适配，先验证公开接口；不默认修改 agent-loop、替换全局工厂或伪装成 LLM 路由 |
| 插件激活 | 新增自带 `cordis.patch.yml` 的 bundle；保留现有 base、web-app 和默认 preset 文件 |
| 共享清单 | 仅增加工作区解析、依赖锁、类型索引和生成目录所必需的条目；不重排现有内容，不手改生成物 |
| 文档与快照 | 新文档和用例优先归属新增组；必要的子系统、架构和双 SDK 更新按实际接口变化处理 |

依赖方向固定为“新增插件 → 现有公开服务”。正常路径不新增“原模块 → 三方授权模块”的依赖。需要补通用扩展点时，先在 T1 列出无法复用的具体接口、最小修改文件、消费者和必要性；把通用接口补充与插件实现分开提交，不在接口里出现 GPT/Claude 特判。没有可满足连续会话要求的低侵入路径时，明确报告冲突和候选方案，不静默扩大核心重构范围或删减功能。

按“必要的公共扩展点、独立插件实现、共享清单及生成更新”组织可区分的提交；相关 README 和 Agent Note 跟随所属逻辑变更，最终 PR 保持完整可构建。每阶段列出新增组以外的变更及理由；不夹带格式化、重命名或现有模块搬迁。需要 rebase 时先检查当前工作区和远端状态，对锁文件及派生目录用既有生成流程恢复，不以保留整份旧文件解决冲突。

<a id="contracts"></a>
## 状态与数据约定

状态需要分别表达账号授权、Harness 连接启用和模型目录可用性。原生登录成功但目录查询失败时，页面显示“已连接，模型加载失败”，不能把认证状态清掉或假装可用。

| 数据或操作 | 约定 |
|---|---|
| Provider 身份 | 稳定的带品牌 ID；执行目标明确区分 `llm-route` 与 `external-agent`，不以模型名猜测 |
| 连接状态 | 未连接、连接中、已连接、需重新授权、运行条件缺失；错误附可恢复操作，不缓存秘密 |
| 授权尝试 | 带品牌 attempt ID、所有者及独立取消信号；通知和输入提示只发给发起者，不广播授权码 |
| 提示回复 | 校验 attempt、prompt、所有者和有效期；终止后的回复拒绝，客户端不自行宣布登录成功 |
| ChatGPT 凭证 | 复用 `llm-pi-ai/openai-codex`；连接设置与凭证写入分别持久化，启动时显式协调部分成功 |
| Claude 登录 | 官方运行时保管；不复制到 Harness 凭证库；只有原生状态确认后才启用连接 |
| 模型目录 | 区分内置目录、原生发现与已验证可调用性；无账号权限信息时不声称“账号全部模型” |
| 默认值优先级 | 已有会话显式选择优先；新会话选择某 Provider 后才应用其默认值；否则保留现有全局默认 |
| 请求进行中 | 请求开始时固定账号连接、执行器和模型；选择变化下一轮生效；授权失效不回退到其他账号或 API Key |
| 断开与重连 | 先停用连接并使未完成登录结果失效，再取消本插件相关请求；GPT 在刷新锁内清理凭证；Claude 不退出其他工具的原生账号 |
| 持久化 | 设置仅存非秘密偏好与连接启用意图；模型选择和执行器会话事实写入 Session；Token、授权码和临时链接不进入 Session |

遇到用户已经配置的 `openai-codex` 路由或 `apiKeyEnv` 覆盖时，明确提示冲突并提供可审查的调整，不覆盖用户配置。若首版不能可靠区分插件拥有的路由，应把该区分作为 T2 的必需项，而不是用删除整个 Provider 配置实现断开连接。

<a id="tasks"></a>
## 开发任务与顺序

按依赖顺序完成 T1 → T2 → T3 → T4 → T5 → T6。GPT 与 Claude 都达到完整验收才算整项完成；仅登录按钮可点击或子任务能返回文本不算完成。

### T1：验证原生能力并定稿执行器方案

核实当前安装的 pi-ai 与固定版本 Claude Agent SDK / CLI 的公开入口，产出一个通过 `dsh` 测试 Profile 启动的最小验证场景。检查 ChatGPT 登录、取消及刷新；检查 Claude 原生登录状态、官方登录启动、模型发现、两轮续聊、停止和恢复。真实账号环节由用户完成官方交互，不读取本机凭证内容；缺少账号或权限时记录未验证项，继续独立开发。

在此任务验证 Claude 能否通过公开的 Agent 注册、生命周期和 UI 扩展接口，由本插件独立管理连续会话并接入现有体验；不预设全局工厂分派改造。先形成新增组外的最小修改清单，清楚区分业务源码、共享清单、文档和生成产物。仅当公开接口确实缺失时提出独立的通用扩展点补充，并列出全部消费者、Session 事件及双 SDK 影响。不把 Claude Agent SDK 包装成伪 `LlmAdapter`，以免两个工具循环重复执行。

完成条件：明确官方能力及固定版本差距、模型目录来源、浏览器回调与运行 Host 的关系、执行器接入点和失败恢复方案，并证明新增组外没有可避免的业务改动。无法获得完整 Claude 上下文或恢复所需事件时，必须在本任务解决记录方案；不能把只存最终文本的实现宣称符合 Session 重建要求。

### T2：实现授权模块与两类 Provider

实现注册及脱敏视图；复用 ChatGPT 现有授权服务，完成连接后路由激活、默认选择持久化和重启协调。实现 Claude 原生能力检查、登录启动及状态确认，并将 Harness 的连接开关与原生全局退出分开。默认只开放已具备可靠归属识别的本机管理端；远程浏览器的回调转发不作为隐式支持。

完成条件：已授权但路由激活失败、重复点击、取消后迟到成功、刷新与断开竞争、插件卸载及外部原生退出都有确定结果；没有凭证进入日志或返回值。只有独立观测可发生分歧时才添加执行中的 invariant companion。

### T3：实现 Remote API 与设置子页

通过 Typert Remote 暴露拟定业务操作 `listProviders`、`beginConnect`、`answerPrompt`、`cancelConnect`、`disconnect`、`listModels`、`setDefaultModel`。这些名称属于待实现接口，不是现有 API。授权流使用受调用者约束的现有流式承载，不新增公开回调服务器或通用 Token 读取接口。

按已确认原型实现独立页面，覆盖初次未连接、连接中、已连接、目录加载失败及失效重登。通用卡片渲染数据，Provider 自己决定连接说明及按钮文案。示例邮箱和模型不得进入生产默认值；无法取得邮箱时展示“账号已连接”。默认选择成功后即时提示，多窗口通过事件失效刷新。

完成条件：页面刷新或关闭会取消它拥有的登录尝试，另一客户端不能查看或回答提示；键盘焦点、取消、深浅主题和窄屏可用。既有 API Key 页面不新增字段且行为保持一致。

### T4：贯通模型选择与连续会话

先完成 ChatGPT 的现有 `ctx.llm` 路由、模型目录和已记录选择链路。随后按 T1 的执行器方案实现 Claude 驱动，贯通新会话、两轮对话、流式文本、原生工具活动、审批、用户问题、停止、重新打开和模型选择。固定版本运行时和 Session 的原生会话标识有明确生命周期，不使用未受管的 Host CLI 回退。

Claude 原生工具只在 Claude 运行时执行一次。审批和提问映射到 Harness 的既有交互能力，不复用一次性插件的“全部拒绝”方式伪装交互完成，也不默认开启 `bypassPermissions`。记录实际可观察的模型输入、输出、工具结果与配置；不可观察的部分按 T1 方案解决，不能编造推理内容或宣称完全回放。

完成条件：会话目录区分执行目标；断开后目录不可选且旧会话明确提示重连；同执行器切换下一轮生效；跨执行器引导新会话。新增模型可见事件更新投影、回放和 TypeScript / Python SDK 预期输出，结构性格式变更遵循相邻迁移且保留旧代文件。

### T5：组合、恢复与分发

在独立 bundle 中声明包导出、Host / Client 编译入口、resolver 依赖与 Profile 安装层，不修改现有 base/web-app 的组合正文；插件只通过现有 `dsh` 启动路径激活。分别验证 Web 与 Desktop 的真实承载，Desktop 不新增后端 HTTP 监听；官方 OAuth 自身的回环回调按实际运行环境处理。缺失 Claude 平台载荷时页面提供可操作的缺失状态，不静默下载或选择不匹配版本。

完成条件：安装后出现设置入口；重启保留连接意图和默认值；关闭或卸载释放流、回调、进程和注册；卸载不删除历史或全局 Claude 登录。新连接尝试遵循配置的超时与释放期限，无未受管子进程。

### T6：完整验收与文档

补齐有行为意义的单测、真实运行时的无密钥测试、带授权的真实服务验收和记录式快照。对不同 Provider 分别记录验证结果，不把 mock 成功算成账号权限验证。更新相关 README、子系统说明、公开 JSDoc 及 Agent Note；若扩展 Agent 工厂或模型目录，同时更新架构和全部消费者。

完成条件：下表用例全部有结果，未验证的真实账号条件明确标出；产品可见 GUI 变更的 PR 附真实服务器与真实模型流程录制的 GIF。原型模拟授权不作为该证据。

<a id="acceptance"></a>
## 验收矩阵

每项至少覆盖成功、拒绝及恢复中与其职责有关的路径；并发测试使用独立目录、动态端口和可控同步，不依赖睡眠抢时序。

| 场景 | 必需结果 |
|---|---|
| ChatGPT 完整流程 | 官方登录 → 模型加载 → 新建会话 → 流式回复 → 工具调用 → 再次对话 |
| Claude 完整流程 | 原生登录 → 连接 → 选择模型 → 新建会话 → 工具及审批 → 再次对话 → 停止 → 重新打开 |
| 凭证与运行时 | 过期、用户退出、运行时缺失、损坏或版本不符分别可诊断，不错误回退 |
| 登录并发 | 双击只启动一次；不同客户端不可串提示；关闭、取消及卸载后迟到结果不重新启用连接 |
| 设置一致性 | 修改默认值后重启仍保留；不改变进行中请求；多窗口更新；配置冲突可恢复 |
| 模型权限 | 空目录、目录失败、模型下线和无权限请求都有明确反馈，不把静态目录视为授权证明 |
| 数据与安全 | 返回值、Remote 事件、Session、日志和错误无 Token；授权提示仅发起者可见 |
| 会话持久化 | 再次打开保留执行器与选择；需要的原生上下文可恢复；不覆盖已发布 Session 旧代文件 |
| 回归 | 原有 API Key 模型、DeepSeek 会话、一次性 Claude 子任务和设置导航通过针对性检查 |
| 隔离与同步 | 新业务集中在新增组；无反向依赖或内部路径耦合；新增组外每个改动都有理由；移除 bundle 后原有 Profile 正常启动 |
| GUI | 中英文、深浅主题、键盘操作和窄屏可用；真实流程 GIF 与交付版本对应 |

<a id="validation"></a>
## 验证与交付

本次交付仅为计划文档。开发时依据实际改动用 dsh-pre-push-checks 选择针对性测试，登录和子进程测试同时遵循 dsh-ci-test-reliability；不默认跑全仓测试或覆盖率。新增包需完成类型检查、配置解析、源码启动及构建产物加载验证；涉及 Session 的修改补双 SDK 和快照，文档执行配对、链接及 doc-sync 检查。

实施顺序允许先验证并交付 GPT 阶段，但完整功能不能省略 Claude 连续会话阶段。T1 的运行时验证决定是否需要升级官方依赖或补最小公共扩展点；全局 Agent 工厂改造不作为默认方案。在这些结果确定前，不把本功能估计成单纯的设置页开发，也不承诺未来 rebase 完全无冲突。
