# Agent Note: Multica 项目文件夹拥有可携带数据

Status: implemented

[English](2026-09-17-portable-multica-projects.md) | 中文

## 问题

创作者将作品移到另一台设备时，需要一起带走版本、已保存草稿、角色配置和对话。设备级项目数据库与独立的全局对话存储使复制一个目录无法满足这个要求。绝对执行路径和进程 ID 不能标识项目在另一台设备上的当前位置或写入者。

## 决策

浏览器创建的每部作品从空目录开始，包含带版本的清单、项目 SQLite 数据库和项目内 Session 存储。清单身份在移动后保持不变；设备数据库保存最近位置与旧项目。打开文件夹时取得独占 SQLite 锁，直至任务、Agent 和数据库关闭后才释放。项目所有权决定重启恢复，不使用其他设备的 PID。未完成的创建或迁移结果保留标记，不能作为完整项目打开。

创建表单在作品名称下方提供目录选择器。成功选择仅绑定当前创建草稿；取消时保留未绑定状态。项目列表顶部和新建卡片共用已有文件夹选择入口，每张项目卡片显示自己的保存位置。客户端声明目录选择 Remote 依赖，使按钮能够调用已装配的宿主服务。

部署的 JSONL 提供方把明确归属的 Session 身份路由到已挂载项目存储。可携带专业 Session 使用 SQLite 事务，不记录绝对工作目录；冻结的任务对象与当前项目挂载决定范围。已发布事件通过既有 Session 扩展点记录。Agent 循环和普通对话存储保持原有行为。项目 Session 头部和已提交事件不可修改。

旧项目迁移复制单个项目的关系数据集合及已初始化对话，保留源数据。关闭时在正式版本之外保存所选编辑缓冲；恢复缓冲时保留其基础版本。备份期间保持项目所有权，拒绝外部链接，在数据复制完成后才发布目标清单。凭据与可执行插件归设备所有。

[项目版本决策](2026-09-10-multica-project-revisions.zh.md)与[专业任务决策](2026-09-11-multica-professional-tasks.zh.md)继续有效：聚合版本、冻结输入、角色权限和人工审查仍是权威约定。本记录负责目录可携带性与 Session 存储位置。

## 考虑过的替代方案

**只移动项目数据库。** 专业对话历史仍依赖原设备，不能满足完整文件夹迁移。

**直接使用普通 JSONL 发布算法。** 其 POSIX 硬链接发布需要 exFAT 不提供的文件系统能力。项目级 SQLite 存储消除了该要求，同时保留共享持久化接口和仅追加语义。

**在项目中保存凭据。** 移动创作内容不意味着授权复制账号凭据。需要供应商时报告缺失依赖，手工内容仍可访问。

## 影响

打开项目文件夹即可重建最近位置。列表删除保留隐藏的设备归属记录，避免未改动的旧项目迁移源重新作为独立项目出现。删除只改动设备登记表，不依赖项目磁盘。该操作不保存草稿或关闭已挂载的运行时，因为这些操作依赖缺失磁盘，会阻断列表删除。元数据刷新保留隐藏标记，只有显式打开成功才恢复可见状态。文件夹、版本、素材和内存草稿保持完整。同一身份的两个副本不能同时挂载；副本不会自动同步或合并。项目锁阻止第二个写入者，但不能协调不同设备上的独立目录副本。已发布角色设置随项目迁移；目标设备可能需要配置工具和供应商账号。

定向文件夹测试覆盖迁移、备份、路径缺失与写入所有权。共享 Session 持久化约定在项目存储上执行；Loader/Agent 循环测试仅复制项目目录到全新 Harness 主目录后继续同一段对话。浏览器预期覆盖文件夹创建与编辑流程。实物移动硬盘故障与跨操作系统硬盘行为仍需单独验证。
