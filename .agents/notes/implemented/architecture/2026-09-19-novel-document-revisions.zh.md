# Agent Note: 小说按文档保存版本，模型建议由作者应用

Status: implemented

[English](2026-09-19-novel-document-revisions.md) | 中文

## Problem

长篇小说需要独立目录、细粒度版本和持续的创作会话。整书快照会让一次段落修改重写无关章节，异步模型回复可能覆盖生成期间产生的新稿。

## Decision

每本小说在自己的目录保存 SQLite 项目数据和 JSONL 会话。全局索引保存目录与 Session 归属。正文、大纲、人物和世界设定使用独立的不可变文本版本；文档顺序与文本版本分别管理。

助手任务捕获文档、版本、可编辑范围和参考文字。作用域只允许当前任务的结构化输出，并拒绝普通会话入口注入的消息。模型不能调用正文写入接口。作者应用建议时，SQLite 事务校验原版本，并同时写入新正文版本和建议处理状态。请求 ID 防止重复应用。

小说 Session 存储路由复用已有 JSONL 提供方，在独立服务域中接收同一 Host 的 Session 事件。已提交的日志代际不移动、不重写；普通会话继续使用原根目录。

## Alternatives considered

**整书聚合版本。** 漫剧的聚合版本满足其项目保存语义；小说章节独立编辑，因此采用独立版本。漫剧仍保留自己的存储决策。

**正文文件与数据库双向同步。** 两份可写主数据需要额外冲突与恢复协议。项目数据库是正文权威来源；导入已有小说目录只注册位置，不猜测外部文本修改。

**模型直接保存。** 这会绕过作者的对比选择，并可能覆盖较新版本。结构化建议与人工应用分别拥有权限。

## Consequences

每次保存的成本与当前文档长度有关，而非整本书长度。 章节列表读取有索引的元数据投影，不解析正文。基础版本过期的建议不能自动应用；作者可以保留本地草稿并重新请求。目录离线、移动和复制后的身份冲突必须明确处理。数据库和 Session 日志是两份不同的持久化资源；模型失败不回滚已经保存的正文。

Loader 集成测试验证独立目录、冲突、历史、建议与取消；真实 Agent Loop 测试验证请求记录、工具拒绝和小说目录内的日志。浏览器组件测试验证创建字段、目标绑定、差异预览和本地草稿保留。
