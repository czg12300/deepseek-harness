# Agent Note: 项目剧本与制作共用可携带项目文件夹

Status: implemented

[English](2026-09-24-multica-project-workspace.md) | 中文

## Problem

项目编辑器将大纲和分集剧本保存为项目修订，但没有文档目录，也没有组织制作产物的位置。复制项目到其他设备时，剧本文件、制作布局和媒体需要一同带走，而设备项目列表应保持独立。

## Decision

独立文件夹项目将已保存的大纲、人物小传和分集剧本镜像为 `scripts/` 中的 Markdown。项目 SQLite 模式 5 索引这些文档，并保存明确确认的剧本摘要、逐集或整片制作单位、画布节点坐标及导入媒体引用。媒体字节位于同一项目文件夹的 `artifacts/`。界面从左侧目录选择剧本、画布或资产目录；现有右侧助手只用于剧本，制作画布使用悬浮输入框。

确认剧本要求已保存且非空的大纲，以及至少一集已保存且非空的剧本。剧本修改后摘要失效，重新确认前不能创建新的制作单位。已有制作单位和媒体仍可读取。策划和编剧助手可提供文本建议，只有用户明确添加后才进入画布；此功能不能通过模型生成图片、视频或音频文件。

## Alternatives considered

**只在设备项目列表保存制作数据。** 复制项目会丢失画布和媒体索引，违反项目文件夹的可携带性。

**将项目保存或内容批准视为制作授权。** 保存的剧本可能尚未完成，审查则决定具体内容版本。明确确认剧本使制作就绪与两者保持独立。

**每个阶段都显示固定的助手侧栏。** 画布和媒体宫格需要可用宽度。剧本浏览保留侧栏；制作在节点旁保留紧凑的悬浮输入框。

## Consequences

模式迁移在新增项目内容表前备份数据库。剧本 Markdown 是已保存项目内容的人可读镜像；大纲和分集仍以项目修订为准。每个导入文件上限为 16 MiB，随项目文件夹保存。模型生成媒体、时间线剪辑和成片导出仍是独立能力。

## Testing

宿主测试覆盖模式迁移、Markdown 文件、剧本确认失效、制作单位、画布修订、媒体导入及重新打开文件夹。无密钥 Web 测试创建项目、编辑剧本、确认剧本、创建制作单位、导入与预览媒体，并重新加载工作台。
