# Agent Note: 源码启动器在安装前解析代理设置

Status: implemented

[English](2026-09-30-source-startup-proxy-preflight.md) | 中文

## Problem

源码启动器将应用数据隔离在 `.dsh-local`，而开发者可用的代理可能保存在 `~/.dsh/.env` 或 macOS 系统设置中。浏览器授权可以到达本地回调，但所选 Harness 数据目录没有代理设置，导致后端无法交换授权码。

## Decision

[`startup.sh`](../../../../startup.sh) 在安装依赖和通过正常的 `dsh --profile web` 入口启动应用前解析网络配置。显式启动变量和所选数据目录的代理设置优先，无效或不可达时明确失败。缺少路由时可使用共享数据目录或 macOS 静态 HTTP 代理设置；自动发现的共享代理不可达时可改用当前系统代理。每次调用都读取当前配置，不持久化复制的端口。

无需依赖安装的 Node 辅助程序使用内置 dotenv 解析器，校验 HTTP 代理 URL，探测各选定监听地址，并统一环境变量的大小写形式。只有代理变量通过私有临时文件中的 NUL 分隔记录传入 shell。程序拒绝控制字符，不将变量值作为 shell 代码求值，诊断信息隐藏代理凭据，并在执行后续命令前删除临时文件。配置始终包含 localhost 绕过项。显式直连模式为子进程清空继承的代理别名。

启动器为现有[出站代理策略](../architecture/2026-08-27-outbound-proxy-policy.zh.md)提供环境变量；应用仍安装自己的正常 dispatcher。此方案不引入应用级全局回退，也不改变认证协议。

## Alternatives considered

向每个数据目录复制共享 `.env` 会积累过期代理设置，还可能复制无关凭据。硬编码 VPN 端口无法适应配置变更。静默替换显式指定但失败的路由可能违背操作者的网络选择。强制请求某个模型提供方会在该提供方故障时阻止无关 profile 启动。

## Consequences

预检在安装或登录前发现代理继承缺失和监听地址关闭。监听地址可达并不证明上游 TLS、提供方访问或账号授权一定成功。仅有 PAC 或 SOCKS 的系统代理需要显式配置受支持的 HTTP 代理。已运行的后端保留启动时的环境，必须重启才能使用变更后的路由。定向测试覆盖配置来源优先级、回退、凭据隐藏、控制字符拒绝、显式直连，以及使用独立临时 TCP 监听地址执行的真实 shell 预检。
